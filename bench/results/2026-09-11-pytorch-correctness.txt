torch._int_mm — why it fails
----------------------------
  rocblaslt error: Cannot read
    torch/lib/hipblaslt/library/TensileLibrary_lazy_gfx900.dat: No such file
  RuntimeError: HIPBLAS_STATUS_INVALID_VALUE when calling
    hipblasLtMatmulAlgoGetHeuristic

A missing Tensile library for hipBLASLt — structurally the same problem this
repo solves for rocBLAS by copying files out of ROCm 6.3.4. The difference is
that no such file exists to copy: TheRock excludes hipBLASLt for gfx900 and
gfx90c entirely (upstream ROCm/TheRock#1062), so int8 quantized paths are out
of reach rather than merely unpackaged.

Notes
-----
Autograd works, so training is possible in principle, not only inference.
bf16 works, which was not assumed — it is the more useful reduced-precision
format for ML work than fp16.

Relative error looks alarming on the reduced-precision rows (3.2e+02) and is
not: it is computed against near-zero reference elements, where any absolute
error divides badly. The absolute errors are what matter there.
